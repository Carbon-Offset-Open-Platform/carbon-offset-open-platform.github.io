Public API · v0 · read-only

Every number, traceable to its source.

The SCOOP v0 API serves the measurements from a metered lab server: energy, emissions, the method behind each figure, and the load curve. Every endpoint is a GET, needs no key, and returns JSON.

Prototype data. These figures come from one lab server (Tufts Auster Center) and exist to make the IEEE P7802 reference implementation inspectable. They are not a production emissions feed.

Base URL

https://website-jade-eta-97.vercel.app/api/v0

Responses are application/json. CORS is open for GET, so browsers can call the API directly. Successful responses carry "status": "ok". Errors return an HTTP status and a detail message.

Quick start

curl https://website-jade-eta-97.vercel.app/api/v0/summary

Pipe through jq to read it more easily:

curl -s https://website-jade-eta-97.vercel.app/api/v0/summary | jq '{energy_kwh, co2_kg, method}'

Endpoints

GET/health

Liveness check. Use it to confirm the service is up before you rely on it.

curl https://website-jade-eta-97.vercel.app/api/v0/health
{"status":"ok","database":"scoop_public.db"}
GET/summary

Headline totals across every measured interval, with the method and the period covered.

curl https://website-jade-eta-97.vercel.app/api/v0/summary
{
  "status": "ok",
  "servers": 1,
  "sessions": 51,
  "measurement_periods": 39,
  "energy_kwh": 0.554967,
  "co2_kg": 0.160941,
  "samples": 2889,
  "first_period": "2026-07-01T21:49:35.199645+00:00",
  "last_period": "2026-07-24T03:11:59.018938+00:00",
  "method": "trapezoid integration of sampled socket power (kWh) x static grid factor (kg/kWh)",

Figures are a snapshot of the record. generated_at is when the response was built, not when the data was measured.

GET/sessions

Measurement sessions, newest first, each with its analysed totals where a session has them. A session with no samples or no analysis shows null for those fields.

Parameters

NameTypeDefaultDescription
limitinteger, 1–20050Maximum sessions returned.
 
curl "https://website-jade-eta-97.vercel.app/api/v0/sessions?limit=5"

Each session has session_id, started_at, ended_at, mode, status, samples_count, and the analysis fields duration_seconds, avg_power_w, peak_power_w, idle_power_w, total_energy_kwh, total_co2_kg and carbon_intensity.

GET/load-curve

Power drawn at each load level: the measured relationship between load and power, not a model. Without session_id it aggregates across every session.

Errors

StatusMeaning
404No measurements for the server_id you asked for.
422A parameter failed validation, for example a limit outside its range.

How the numbers are made

Each figure is computed in two steps. Socket power is sampled roughly every six seconds from a metered smart power strip and integrated over time with the trapezoid rule to give kilowatt-hours. Those kilowatt-hours are multiplied by a static grid carbon intensity factor in kilograms of CO₂ per kilowatt-hour. The factor used is recorded on each row as carbon_intensity_used.
